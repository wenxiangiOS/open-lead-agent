# R001 开场白需求

## 1. 文档定位

本文档定义开场白的需求、规则、配置和实现位置。

## 2. 需求

用户首次进入对话时，系统可以自动发送开场白，引导用户表达来意，降低用户开口成本。

开场白不是字段追问，不消耗任何字段的有效询问次数。

## 3. 背景

好的开场白会影响后续资料收集效率。

如果一上来就像表单一样问字段，用户容易产生压力；如果开场白过空，又无法引导用户进入业务场景。

## 4. 规则

- 开场白由模板配置，不写死在代码里。
- 开场白可以带快捷回复。
- 开场白不算有效询问。
- 开场白不应该连续索要多个字段。
- 用户首轮只是打招呼时，可以轻问来意或进入第一个低压问题。
- 用户首轮乱码、错字、无法稳定理解时，不应直接切入字段采集。
- 用户首轮已经主动提供资料时，应先收集已提供的信息，再自然推进下一步。

## 5. 配置

```yaml
opening:
  enabled: true
  message: "你好呀，我是课程顾问。你是想给孩子了解课程，还是自己想了解学习规划？"
  greeting_response: "你好呀，你可以先简单说下想了解的情况，我先了解一下。"
  quick_replies:
    - 给孩子了解
    - 自己想了解
    - 先问下收费
```

## 6. 示例

```text
系统：你好呀，我是小缘。你是认真想找对象，还是想先了解一下服务？
用户：你好
AI：你好呀，你也可以先简单介绍下自己，我先了解下你的情况。
```

这个例子里，用户只是回应开场问候，系统先低压承接，不立刻进入 `sex`、`age` 等字段采集。

```text
系统：你好呀，我是小缘。你是认真想找对象，还是想先了解一下服务？
用户：我来自深圳
AI：深圳发展机会还挺多的呀，你现在是做什么工作的呀？
```

这个例子里，开场白不算字段询问；用户主动提供 `location=深圳` 后，系统顺着上下文问相近核心字段 `occupation`。

## 7. 实现位置

- `src/templates/config.py`：`OpeningConfig`
- `src/policy/opening.py`：开场问候缓冲策略
- `src/cli.py`：终端测试工具展示开场白
- `src/conversation/engine.py`：对话主链消费模板状态

## 9. 当前状态

已实现基础版。已支持 `greeting_response`：空资料、首轮简单问候时先低压承接，不立刻追问字段。

后续可增强：

- Web/API 层更明确地区分“自动开场白”和“用户首轮消息”。
- 首轮乱码/异常输入策略可进一步沉淀成独立 opening guard。
