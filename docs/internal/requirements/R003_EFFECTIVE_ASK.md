# R003 有效询问需求

## 1. 文档定位

本文档定义什么情况下字段询问算“有效询问”，以及 `ask_limit` 应该如何消耗。

## 2. 需求

系统不能把“AI 问出口了”简单等同于“有效询问 +1”。

有效询问必须结合用户下一轮回复判断。这样才能避免用户中途问收费、隐私、门店、靠谱不靠谱时，被系统误判为“不回答资料”，导致字段过早跳过。

## 3. 背景

线索收集对话不是问卷。

真实用户经常会在资料收集中插入问题或顾虑，例如：

- 怎么收费？
- 有门店吗？
- 为什么问这么多？
- 会不会泄露隐私？
- 能不能先看照片？

这些回复不是对当前字段的有效拒绝，也不是敷衍。系统应该先答疑，再回到原来的主线字段。

## 4. 核心规则

### 4.1 主字段 main_target

`main_target` 是本轮主线字段。

| 用户回复类型 | 是否有效 | 行为 |
| --- | --- | --- |
| 回答了主字段 | 有效 | 收集字段，不再计为缺失 |
| 明确拒绝主字段 | 有效 | 计数 +1，可标记 skipped |
| 敷衍主字段 | 有效 | 计数 +1，后续换问法或跳过 |
| 回复无关资料 | 有效 | 主字段计数 +1，同时被动收集无关资料 |
| FAQ / 顾虑 / 换话题 | 无效 | 不计数，先答疑，再回到 `main_target` |

### 4.2 顺带字段 side_target

`side_target` 是本轮可选顺带字段，不能抢主线。

| 用户回复类型 | 是否有效 | 行为 |
| --- | --- | --- |
| 回答了顺带字段 | 有效 | 收集字段 |
| 明确拒绝顺带字段 | 有效 | 计数 +1，可标记 skipped |
| 没回答顺带字段 | 无效 | 不计数 |
| 只是内部计划但没问出来 | 无效 | 不计数 |

### 4.3 低优字段 low

低优字段不主动问，所以不存在有效询问。

用户主动说了就被动收集，例如身高、体重、姓名等。

## 5. 示例

### 示例 1：FAQ 不消耗主字段次数

```text
AI：你今年大概多大呀？
用户：怎么收费？
```

结果：

- `age` 不计有效询问次数
- 系统先回答收费问题
- 答完后可以自然回到年龄主线

### 示例 2：敷衍消耗主字段次数

```text
AI：你今年大概多大呀？
用户：嗯
```

结果：

- `age` 计数 +1
- 后续可以换一种低压说法再问

### 示例 3：无关资料会消耗主字段次数

```text
AI：你今年大概多大呀？
用户：我在深圳
```

结果：

- `age` 计数 +1
- `location=深圳` 被动收集
- 下一轮可以顺着深圳问相近字段，例如职业

### 示例 4：顺带字段没回答不计数

```text
AI：你现在主要做什么工作呀？如果方便的话，也可以顺带说下收入区间。
用户：老师
```

结果：

- `occupation=老师` 被收集
- `monthly_income` 不计数

### 示例 5：顺带字段明确拒绝才计数

```text
AI：你现在主要做什么工作呀？如果方便的话，也可以顺带说下收入区间。
用户：老师，收入不太方便说
```

结果：

- `occupation=老师` 被收集
- `monthly_income` 计数 +1，可标记 skipped

## 6. 配置

字段可以配置默认有效询问次数：

```yaml
field_groups:
  core:
    - key: age
      label: 年龄
      ask_limit: 2

  medium:
    - key: monthly_income
      label: 月收入
      ask_limit: 1

  low:
    - key: height
      label: 身高
      ask_limit: 0
```

默认建议：

- `core`：2 次
- `medium`：1 次
- `low`：0 次

## 9. 当前状态

已实现主字段基础规则。

当前共识：

- FAQ / 顾虑 / 换话题不消耗当前字段次数。
- 主字段回复无关资料时，会消耗一次有效询问，同时被动收集无关资料。
- 低优字段只被动收集。

后续可增强：

- 更精确地区分 `side_target` 是否真的被问出口。
- 对“敷衍”和“拒绝”的分类继续细化，避免误伤正常短答。
