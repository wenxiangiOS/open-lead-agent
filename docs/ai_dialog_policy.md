# AI 对话策略方案

## 一、方案目标

### 1.1 目标定义

这套方案的目标不是单纯“把字段问全”，而是同时满足 4 个要求：

| 目标 | 说明 |
|---|---|
| 可实行 | 规则明确，能直接拆成代码逻辑 |
| 能落地 | 不依赖过度理想化判断，不引入失控复杂度 |
| 更拟人化 | 不再像流程机，能承接、转场、顺着用户聊 |
| 收集效率不丢失 | 核心字段仍然要稳定推进 |

### 1.2 设计原则

- 保留字段分级
- 保留优先顺序，不用固定死顺序
- 保留每轮 `1主 + 1顺带`
- 联系方式继续走现有专门逻辑
- 不再扩张复杂状态机
- 增加“拟人化表达层”，但规则必须能实现、能测试

## 二、字段分级总览

### 2.1 字段分类

| 级别 | 字段 | 收集策略 | 主动询问上限 | 不答处理 |
|---|---|---|---:|---|
| 核心字段 | 性别、年龄、学历、职业、工作地、联系方式 | 必须主动收集 | 2次 | 达上限后标记跳过/延后 |
| 准核心 | 婚况 | 必须收集 | 2次 | 达上限后先跳过，后续可被动收 |
| 中等字段 | 月薪、择偶要求 | 自然穿插收集 | 1次 | 不追问，后续仅被动提取 |
| 低优字段 | 身高、姓名、体重 | 永不主动问 | 0次 | 用户主动说才记录 |

### 2.2 各字段详细规则

| 字段 | 级别 | 主动询问上限 | AI 指令要点 |
|---|---|---:|---|
| 性别 | 核心 | 2次 | 前两轮优先确认；第2次可解释用途 |
| 年龄 | 核心 | 2次 | 第2次可接受模糊值 |
| 学历 | 核心 | 2次 | 第2次可解释匹配用途 |
| 职业 | 核心 | 2次 | 第2次可表示“多了解你一点” |
| 工作地 | 核心 | 2次 | 第2次接受模糊地区 |
| 联系方式 | 核心 | 独立策略 | 沿用现有电话/微信逻辑 |
| 婚况 | 准核心 | 2次 | 柔性确认，不像审查 |
| 月薪 | 中等 | 1次 | 必须带“不方便说也没关系” |
| 择偶要求 | 中等 | 1次主动+持续被动提取 | 问一次即可，后续持续提取 |
| 身高 | 低优 | 0次 | 永不主动问 |
| 姓名 | 低优 | 0次 | 永不主动问 |
| 体重 | 低优 | 0次 | 永不主动问 |

## 三、收集顺序与调度规则

### 3.1 优先顺序

不是固定死顺序，而是优先顺序。

第一优先：
- 性别
- 年龄
- 工作地

第二优先：
- 学历
- 职业
- 婚况

第三优先：
- 联系方式

穿插补充：
- 择偶要求
- 月薪

被动收集：
- 身高
- 姓名
- 体重

### 3.2 每轮调度规则

| 规则项 | 调度规则 |
|---|---|
| 主目标字段 | 每轮只推进1个主目标字段 |
| 顺带补充字段 | 每轮最多顺带1个相关字段 |
| 已知字段 | 已提取到的字段不再重复问 |
| 连续追问限制 | 同一字段不能连续两轮都问 |
| 用户疑问 | 先回答疑问，再回主线 |
| 低优字段 | 不允许主动打断主线去问 |

### 3.3 中等字段穿插时机

| 触发场景 | 穿插字段 | AI 指令 |
|---|---|---|
| 年龄已确认后 | 择偶要求 | 自然问对另一半期待，不强求完整 |
| 婚况/感情话题出现后 | 择偶要求 | 顺着感情话题继续聊 |
| 职业已确认且节奏稳定 | 月薪 | 轻问收入，并明确“不方便说也没关系” |
| 用户主动提及收入待遇 | 月薪 | 顺势确认模糊收入范围 |

## 四、拟人化增强层

### 4.1 承接规则

每次提问前，优先做承接，不要直接硬问。

承接顺序：
1. 承接用户情绪
2. 承接用户内容
3. 给一句轻反馈
4. 再推进主目标字段

示例逻辑：
- 用户积极回答：轻反馈后继续推进
- 用户犹豫：先安抚，再降低问题压力
- 用户开玩笑：可轻接一句，再回主线
- 用户敷衍：不要立刻压问，先换轻方式
- 用户防备：先解释用途，再决定是否继续问

### 4.2 转场规则

从一个字段切到另一个字段时，必须经过转场。

标准转场结构：
`承接上一句 → 反馈/认可 → 进入下一字段`

禁止：
- 刚问完职业，下一句直接问收入
- 刚问完年龄，下一句直接问婚况且无过渡

### 4.3 非收集型互动规则

为了更像真人，允许少量非收集型互动。

规则：
- 每收集 2 到 3 个有效字段，可插入 1 轮轻互动
- 轻互动只做短反馈，不长聊
- 下一轮必须回到主线

可做：
- 简短认可
- 轻微共情
- 对择偶表达做一句自然反馈

不可做：
- 连续两轮不收集
- 输出大段建议
- 变成陪聊

### 4.4 用户类型适配

| 用户类型 | 特征 | 对应策略 |
|---|---|---|
| 配合型 | 回答直接，信息量高 | 推进稍快，允许1主+1顺带 |
| 保守型 | 回答短，对敏感问题回避 | 多解释、少压迫、少追问 |
| 敷衍型 | “嗯”“还行”“再说吧”较多 | 放慢推进，更多被动提取 |
| 话题型 | 愿意展开讲要求、生活、经历 | 先顺着聊，再从中提取字段 |

### 4.5 记忆回用规则

这是拟人化提升最大的新增点之一。

规则：
- 用户已经说过的信息，后续回复里要自然回用
- 回用要短，不要像复读资料
- 回用的目的是让用户感到“被听见了”

允许的回用：
- 地区
- 职业
- 择偶要求
- 已表达的偏好
- 已表达的顾虑

示例：
- “你刚刚说更看重成熟稳重，这个我记住啦”
- “你在杭州的话，同城筛选会更方便一点”

禁止：
- 大段重复用户资料
- 像数据库回显

### 4.6 情绪识别与情绪承接

新增可落地情绪标签：

| 情绪标签 | 识别信号 | 处理方式 |
|---|---|---|
| 放松/配合 | 主动回答、信息量多 | 正常推进 |
| 犹豫 | “这个也要说吗”“嗯…” | 先缓冲，再降低门槛 |
| 防备 | “你们靠谱吗”“干嘛问这个” | 先解释用途/隐私，再推进 |
| 敷衍 | “还行”“一般”“再说吧” | 暂不加压，换轻方式或跳过 |
| 调侃/玩笑 | “你查户口呢”“问这么细” | 轻接一句，再回主线 |

## 五、字段问法层级

### 5.1 第一次提问

原则：
- 轻
- 短
- 顺着话题
- 不解释过多

适用：
- 用户配合
- 前几轮
- 不太敏感的字段

### 5.2 第二次追问

原则：
- 必须换问法
- 先承接
- 可解释用途
- 可降低回答门槛

适用：
- 核心字段
- 婚况
- 用户第一次回避但未明确拒绝

### 5.3 敏感字段问法层级

| 问法层级 | 使用场景 |
|---|---|
| 直接轻问 | 用户配合度高时 |
| 柔和确认 | 用户稍保守时 |
| 带解释轻问 | 第2次追问或用户表达顾虑时 |
| 降门槛问法 | 接受模糊回答时 |

### 5.4 婚况问法分层

| 问法类型 | 使用场景 |
|---|---|
| 自然带出型 | 聊到找对象、感情状态时 |
| 轻确认型 | 已聊到部分背景信息后 |
| 缓冲解释型 | 用户谨慎或第一次没答 |

### 5.5 择偶要求问法分层

| 问法类型 | 使用场景 |
|---|---|
| 开放型 | 用户愿意表达时 |
| 轻提示型 | 用户表达少时 |
| 延展型 | 用户已经说出一点偏好时 |

## 六、字段状态管理

### 6.1 推荐实现状态

为了可落地，不建议保留过多复杂状态。实现层建议只用 5 种：

| 状态 | 含义 |
|---|---|
| unasked | 未主动问过 |
| asked_once | 已问1次未收集到 |
| asked_twice | 已问2次未收集到 |
| collected | 已收集到 |
| skipped | 达上限或明确不答 |

### 6.2 实现建议

- `passive_collected` 不单独存状态，直接算 `collected`
- `rejected / deferred` 不单独做主状态，可记在日志或上下文原因里
- 这样更利于实现和调试

## 七、智能提取策略

### 7.1 核心原则

从每条用户消息中，尝试提取所有可能字段，不局限于当前主目标字段。

### 7.2 提取范围

- 核心字段：性别、年龄、学历、职业、工作地、联系方式
- 准核心字段：婚况
- 中等字段：月薪、择偶要求
- 低优字段：身高、姓名、体重

### 7.3 提取规则

- 当前没在问，也要提取
- 一句话多个字段，一次性全部提取
- 后续更清晰值可覆盖模糊值
- 模糊值允许归一化存储
- 低优字段只提取，不反向触发追问
- 用户情绪和配合度也要同步更新为对话标签

## 八、联系方式触发规则

### 8.1 进入联系方式逻辑的时机

| 触发条件 | 是否进入 |
|---|---|
| 已拿到4个及以上核心/准核心字段 | 是 |
| 已拿到年龄+工作地+职业/学历之一+婚况 | 是 |
| 只拿到1-2个基础字段 | 否，继续完善画像 |
| 用户主动提出愿意留联系方式 | 是，可提前进入 |

### 8.2 边界说明

- 联系方式怎么问，不改你现有策略
- 这套方案只控制“何时进入”
- 进入联系方式阶段时，仍允许被动收集其它字段
- 不要在资料基础太薄时过早切入联系方式

## 九、用户疑问处理

### 9.1 优先原则

用户疑问 > 字段收集

流程：
- 检测疑问
- 暂停收集
- 回答疑问
- 简短确认是否还有问题
- 回到原主目标字段

### 9.2 疑问类型

- 收费
- 隐私
- 信任
- 用途

### 9.3 回答要求

- 先回应顾虑
- 再解释
- 语气像真人客服/红娘
- 回答后不要突然跳到无关字段

## 十、收尾与异常处理

### 10.1 收尾条件

| 收尾类型 | 触发条件 |
|---|---|
| 标准完成 | 联系方式完成 + 至少4个核心/准核心真实值 |
| 可接受完成 | 联系方式完成 + 至少3个核心/准核心真实值 |
| 提前收尾 | 用户明显不愿继续 / 双拒联系方式 / 持续低信息 |

### 10.2 异常情况处理

| 异常情况 | 处理指令 |
|---|---|
| 核心字段未答1次 | 后续换方式再问1次 |
| 核心字段未答2次 | 标记 skipped，继续下一个字段 |
| 准核心字段未答2次 | 先跳过，后续如用户主动提到再补收 |
| 中等字段未答 | 不追问，转回主线 |
| 用户中途离开 | 保存断点，下次从未完成主目标继续 |
| 用户连续低信息回复 | 放慢节奏，优先承接，必要时提前收尾 |
| 用户主动跳话题 | 先承接，再提取字段，随后回主线 |

补充约束：

- 高风险提前收尾场景，例如年龄限制、已婚、分居、离异手续未办妥、LGBT，不默认切到 AI 自由生成。
- 这类场景优先使用多变体预设话术，既保持合规和稳定，也尽量降低固定模板的机械感。

## 十一、技术落地建议

### 11.1 实现拆分

建议拆成 4 层：

| 模块 | 职责 |
|---|---|
| 字段调度层 | 决定当前主目标字段和顺带字段 |
| 提取层 | 从用户消息中提取全部字段 |
| 表达层 | 负责承接、转场、问法层级 |
| 联系方式层 | 继续使用现有独立逻辑 |

### 11.2 最小实现顺序

1. 先做字段优先级调度
2. 再做婚况提升和中等字段穿插
3. 再做承接/转场模板
4. 再做用户类型适配
5. 最后做记忆回用增强

这样最稳。

### 11.3 当前实现状态

当前项目里，这套方案已经不是讨论稿，而是已经接到主流程：

- 已新增字段调度层：`src/services/profile_collection_policy.py`
- 已接入主对话流程：`src/services/core/dialogue_manager.py`、`src/services/core/chat_service.py`
- 已保留联系方式独立逻辑：`src/services/contact_collection_service.py`
- 已将 `request.sex` 作为可信输入优先落档，减少重复确认性别
- 已收紧追问计数：低优字段不计主动追问，中等字段不走多轮追问
- 已把资料成熟度判断从旧的固定字段链路改为“可服务画像阈值”

### 11.4 Prompt 落地与拟人化优化

`src/services/prompts.py` 已按这套方案做过多轮收敛，当前已完成的重点包括：

- 主提示词已切到“核心 / 准核心 / 中等 / 低优”四层策略
- 已加入当前主目标字段、顺带字段、用户类型、联系方式可进入状态
- 已限制每轮 `1主 + 1顺带`，避免连珠炮提问
- 已明确低优字段只被动提取，不主动追问
- 已增加联系方式主目标锁定，避免进入联系方式后又被月薪、低优字段打断
- 已降低模板味：减少机械“小哥哥/小姐姐”、过度语气词、夸张吹捧和营销式开场
- 已收紧离异确认、分居结束、二次追问示例，使表达更自然但不破坏业务刚性

### 11.5 当前已验证的行为结论

基于真实 AI 回归，当前这套实现已经验证过以下关键行为：

- 资料未成熟时，不会主动追问身高、体重、姓名
- 用户先提问时，会先答疑，再回主线
- 资料成熟后，才进入联系方式
- 用户主动给出多个字段时，不会回头逐项重复盘问
- 用户分居中时，会礼貌结束，不继续推进
- 用户双拒联系方式时，会走到收尾，不会无限纠缠
- 用户只留微信时，不会卡死在联系方式阶段
- 离异手续办妥后，会继续回主线，而不是误结束

## 十二、自动化测试方案

### 12.1 必测项

| 测试点 | 断言 |
|---|---|
| 核心字段优先 | 未收完核心字段前，不应优先问中等字段 |
| 婚况优先级提升 | 婚况优先于月薪和择偶要求 |
| 低优字段永不主动问 | 调度器不能返回身高/姓名/体重 |
| 核心字段最多2次 | 第3次不能再主动追问 |
| 中等字段最多1次 | 第2次不能主动再问 |
| 一句话多字段提取 | 可同时提取年龄+职业+地区等 |
| 联系方式触发条件 | 只有达到条件后才进入联系方式逻辑 |
| 回答疑问后回主线 | 回答收费/隐私问题后回原目标字段 |
| 承接与转场合规 | 回复意图正确，不直接硬切新字段 |

### 12.2 测试分层

- 单元测试：字段调度器
- 单元测试：提取器
- 集成测试：多轮资料收集流
- 真实AI测试：只测意图和状态，不测精确文案

## 十三、最终结论

| 维度 | 最终规则 |
|---|---|
| 核心字段 | 性别(2次)、年龄(2次)、学历(2次)、职业(2次)、工作地(2次)、联系方式(独立逻辑) |
| 准核心 | 婚况(2次，柔性确认) |
| 中等字段 | 月薪(1次)、择偶要求(1次主动+持续被动提取) |
| 低优字段 | 身高、姓名、体重，不主动问，只智能提取 |
| 收集顺序 | 优先顺序：性别/年龄/工作地 → 学历/职业/婚况 → 联系方式 |
| 调度规则 | 每轮1个主目标，最多1个顺带字段 |
| 拟人化增强 | 承接、转场、用户类型适配、轻互动、记忆回用、情绪识别 |
| 联系方式 | 沿用现有逻辑，只增加进入时机控制 |
| 状态实现 | 推荐5状态实现，避免过度复杂 |
| 落地方式 | 先改调度，再改表达层，再补测试 |
